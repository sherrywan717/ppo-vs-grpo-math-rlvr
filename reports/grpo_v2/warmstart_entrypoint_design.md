# Guarded GRPO-v2 warm-start entrypoint

The CPU-safe CLI validates exact config path/SHA, manifests/data registry, seed, BF16, LoRA, 928/640/1,088 length gates, 256 samples, one epoch, batch 4, GA4, effective batch 16, and 16 optimizer/global/scheduler steps before delayed model imports. Real execution additionally requires dual confirmation, clean `improve/grpo-v2`, both offline variables, the canonical local revision, and a new run directory.

Completion-only encoding independently tokenizes prompt and assistant target, rejects each separate cap, then rejects actual combined length above 1,088. Prompt/generation-boundary and padding labels are -100; assistant target and EOS are active. Online guards require 256 unique samples, 64 microsteps, 16 optimizer/global steps, one epoch, and finite losses. Every consumed batch atomically updates the ordered sample/counter/supervised-token prefix; every logged step atomically updates metrics. The checkpoint is policy-adapter-only plus optimizer/scheduler/Python/NumPy/CPU/CUDA RNG, trainer/runtime/data cursor, identities, and SHA inventory. Base weights and external checkpoints are forbidden. GRPO consumes only the policy adapter and its SHA; it initializes a fresh GRPO optimizer and never inherits SFT momentum. Parent-process GPU release and persistent backup remain launcher finalization requirements.
